## 3. 三处缺口与关闭方式

### 3.1 同一 turn 冲突终态

- Bridge 记录首次接受的 terminal type；完全相同的重复终态保持幂等，不同 terminal type 立即拒绝为 `xiaoban_progress_terminal_conflict`。
- `turn.completed` 后插入同 turn 的 `turn.failed` 时，最终正文不释放，`onSnapshot` 为 0，交付状态不进入 generated/delivering/delivered。
- DeliveryStore 增加同一 turn 冲突终态冻结负例，第二终态不能改写已接受的 durable terminal。

### 3.2 真 MoA 后置帧早于 turn

- 绑定耐久请求下，`xiaoban.moa.outcome` 只允许在 `turn.completed` 后、usage/aggregate 前进入。
- `xiaoban.moa.usage` 只允许在 turn terminal 后进入；成功 terminal 还必须先有 outcome。
- 带 finish reason/aggregate usage 的结束帧必须同时具备 finish reason 与 usage，且只允许在 turn terminal、tool 全关闭、对应账本就绪后进入；`stop` 只能对应 `turn.completed`。
- outcome、usage、aggregate 任一被移到 `turn.started` 前，均稳定拒绝为 `xiaoban_progress_order_invalid`，不产生正文快照或交付推进。

### 3.3 v2 turn 混入 v1 tool lifecycle

- Bridge 将已接受 turn 的 `progressSchema` 绑定到整轮；turn terminal 与 tool lifecycle 必须使用同一 schema，否则拒绝为 `xiaoban_progress_schema_conflict`。
- DeliveryStore 同时做持久化防线：已接受 turn 之后，schema 不一致的 turn/tool event 不落库且不提升 version。
- 正向 v2 fixture 已删除混合 v1 tool lifecycle；完整 v1 tool 生命周期不能再藏在 v2 turn 中通过。
