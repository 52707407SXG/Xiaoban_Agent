## 1. 五个唯一运行合同

后文只引用 `K1–K5`，不得换名字再定义一遍。`K1–K5` 与 `G1–G4` 都只是计划内定位标签，**不授权新增同名类、文件、状态、注册表或总控层**。

### K1：唯一 Loop

模型始终持有原始任务；有工具调用就真实执行并把结果送回同一回合。只有没有待执行工具、没有合法 steer/新输入且 Provider 未要求继续时才形成 final。简单聊天自然回答，复杂任务可按需 Plan。代码不猜业务意图、不替模型选业务路径、不替模型回答。

### K2：ToolResult

每次真实调用至少绑定：

```text
requestId / turnId / callId / toolName
dispatchState: not_dispatched | dispatched
outcome: success | empty | not_found | denied | failed | unknown | cancelled
retrySafe / recordRefs / coverage / truncated / continuation（适用时）
```

结果只分三层：服务端私有审计、当前身份可见且完成任务所需的有界 `modelResult/modelError`、网页严格脱敏摘要。失败不能吞；`dispatched + unknown` 先由幂等、readback 或账本裁决，模型不得盲目重复副作用。

### K3：动作边界

每个具体动作由服务端校验登录身份、owner/team/company、DataScope、资源归属、适用 credential/binding、schema 和参数。写动作继续要求独立确认、revision/CAS、幂等、事务、commit/readback 和权威 receipt。AUTH、OUT 或站内 ID 只是定位钥匙，不是越权凭证。

### K4：回复与终态

正常业务只有一次模型 `agent-reply`。无法合法或物理取得可信 final 时，取消、Provider/进程 fatal、路由错配或耐久终态失败只能产生独立中性的 `system-receipt`，不得冒充小伴。

硬事实检查只允许：

```text
typed claims + evidenceRefs + receipt/ledger
  → pass | hard_contradiction
```

它不读用户原文、不解析中文、不选工具、不判断业务是否完成、不生成答案，也不拥有独立状态、prompt 或回复出口；优先复用现有 result/receipt 字段，不新建全局组件。旧 `CompletionGuard` 文件、名称和调用链必须删除。

### K5：投递、账本与事件

一个 reply owner、一个 terminal owner、一个 delivery owner、一个普通账本 owner、一个 MoA 账本 owner。每个 paid-call reservation 只收口一次：`not_dispatched` 释放且不扣费；`dispatched + usageStatus=reported` 按权威 usage 结算；其余 dispatched call 保持 `settlementBlocked=true`，不得漏账、重复扣费或按 0 猜结算。

真 MoA 的 final-slot 耐久确认若在 Provider worker/call reservation 创建前失败，calls 必须保持空，slot/wave 收口为 failed 并记录独立 errorCategory；不得冒充 Provider timeout、usage 或 `not_dispatched` call。

所有公开事件都有 `eventId/requestId/version`；`turnId` 只在 turn 建立后出现，`callId` 只在调用 reservation 建立后出现。pre-turn 失败使用 `phase/errorCategory/受限 traceRef`，不得伪造 ID；网页不展示参数、正文、内部路径或 reasoning。
